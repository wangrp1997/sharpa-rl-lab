# 在手圆柱旋转与跨手迁移评估

日期：2026-09-28。检查对象：当前 `baseline` 分支（HEAD `3c434e4`）、`docs/`、现存 `logs/live_diag/`，以及入口实际引用的 `/home/rw/Documents/` 下三份规划器适配代码。本次没有启动 Isaac/Docker 实验，没有修改控制器。做了日志汇总、离线 USD 几何读取和一个凸包判据反例。

用户当前目标：保留 Sharpa 的初始化，在 256 环境筛选稳定握持后，在当前物理状态上持续用指尖旋转圆柱；算法原型最终用于不同的手，不采用原仓库 RL 策略。真手是五指绳驱动，指尖有三维力及阵列图像数据，可考虑相机测物体位姿。独立电机数、关节角反馈及绳张力反馈尚待确认。

## 判断

当前结果说明这些具体适配版本没有完成持续旋转。它们尚不足以证明 Jiang、FREE、DROP 原方法不适用，也不足以判断非 RL 路线的迁移上限。需要先排除任务模型、执行动作和评估指标的不一致。

建议主线是：已知圆柱、可测位姿、触觉保载、小角度操作、接触交接与换指。跨手复用任务层和接触调度，每只手提供自己的驱动、运动学和触觉适配。不把未知形状重建作为第一阶段的前提。

## 已确认的实现问题

### 1. 初始化筛出的稳定握持不保证是多个独立指腹在承载

`rl_isaaclab/tasks/inhand_rotate/sharpa_wave_grasp_env.py:48` 的筛选统计 10 个传感器：五块 elastomer 和五段 DP，要求其中至少 3 路力超过 0.5 N。它既不是“至少三个指腹”，也不是“至少三根不同的手指”。

后续控制器只读前五路的 `normal_force_matrix_w`。因此筛选合格与控制器可观测、可操纵的接触集合不同。静态撑过重力方向切换，也不代表当前接触允许轴向旋转或释放一指。

保留现有初始化，在冻结前后增加任务资格检查：实际指腹载荷、关节/驱动余量、小切向试探的真实旋转响应，以及空闲手指能否建立备用接触。优先在有三个以上有效指腹、且有换指空间的姿态上打通循环；接触数本身不构成稳定性保证。仿真中可额外记录非指腹接触作评估诊断，不将这些仿真专有力当作部署观测。

### 2. 圆柱尺寸是对齐的

离线读取 `assets/cylinder/cylinder.usd`，未施加环境缩放时包围盒为 `[-0.04,0.04] × [-0.04,0.04] × [-0.032,0.032] m`，半高已是 32 mm。当前抓取配置 `scale_range=[0.5,0.5,1]`，只把半径缩到 20 mm，Z 向缩放是 1，半高仍是 32 mm。

三个外部规划器写的也是半径 20 mm、半高 32 mm：

- Jiang：`/home/rw/Documents/in_hand_manipulation_2/high_level/planner/ddp/tasks/sharpa_qsim_server.py`，`CYLINDER_HALF_LENGTH=0.032`。
- FREE：`/home/rw/Documents/Complementarity-Free-Dexterous-Manipulation/models/sharpa/kinematics.py:53`，`CYLINDER_HALF_HEIGHT=0.032`。
- DROP：`/home/rw/Documents/mujoco_mpc/mjpc/tasks/sharpa/task.xml:35`，`size="0.02 0.032"`。

尺寸不是这次没有持续旋转的原因。

### 3. 当前 Jiang 入口执行的是另写的控制逻辑

`rl_isaaclab/scripts/jiang_qsim_turn.py:461` 调用服务器，但 `:479` 开始用 `tangential_roll` 构造实际命令，后续 release/swing/regrasp 也手工生成动作，没有执行返回的 `result["du"]`。日志中的 `du_norm`、`yaw_pred` 来自求解器，`du` 却是另一条动作链路。这些字段不能直接当成同一动作的预测与实测对照。

`docs/baseline_attempts.md` 单列的 `jiang_ordered_40.jsonl` 是历史实验，需要保留它与当前混合控制版本的区别。应拆分或明确标记 planner 与 tangential/gait 两种模式，并保存原始动作、修改后的动作和实际执行动作。

### 4. Jiang 的物体模型不能预测悬空支撑失败

实际服务器 `sharpa_qsim_server.py:73` 将圆柱根节点固定在世界中，只留下绕世界 Z 的 revolute joint；状态为 22 关节加 1 个 yaw，每步反馈也只有 q 和 yaw。Isaac 中圆柱则可平移、倾斜和掉落。

规划模型不必与仿真完全一样，但若把支撑、平移、倾斜从模型删掉，就必须由另一个经过验证的闭环处理这些自由度。当前不能用这个单自由度模型的成功预测证明自由圆柱可持续转动。

此外，Jiang/FREE 初始化时将加载指腹的代理球压入圆柱约 1.5 mm，并把未加载指腹代理球移远。这是人为构造的接触代理，不是经过接触运动与力响应验证的真实指腹几何。它也会改变建立新接触的能力。

### 5. DROP 的坐标转换没有同步变换重力

`rl_isaaclab/scripts/drop_mjpc_turn.py` 的 `cylinder_in_hand` 将圆柱位姿转换到手基座坐标。MuJoCo `task.xml` 的手也建在该坐标系下，但 `<option>` 未设置变换后的重力，服务器没有更新它。

按当前手初始姿态，世界重力转换到手坐标应约为 `(-9.218, 0, -3.355) m/s²`，而 MuJoCo 默认仍是 `(0,0,-9.81)`。应统一世界坐标，或同步转换重力等全部空间量。服务器还每次把 qvel 清零；对于动态规划器，这也需要作为明确的近静态近似验证。

### 6. 动作后处理大幅改变求解结果

- FREE `keep_loaded_curl` 固定冻结时未承载的手指，删除承载指的张开分量，接触集合使用 `loads0`。
- DROP `keep_loaded_curl` 除上述限制外还固定所有侧摆，随后将增量裁到 ±0.02 rad。执行端留下的主要是屈曲动作，因此“只会继续捏紧”不能只归因于 DROP 求解器。
- FREE 以测得 q 输入模型，却将增量加到 `prev_targets` 上（`free_explicit_turn.py:321`）。DROP 也将相对实测 q 的目标差，加到旧位置目标上。已有伺服误差会变成额外目标偏置；承载时旧目标偏置又可能承担预紧，不能未经验证一律换成实测 q。

应定义明确的驱动接口：绝对位置目标或相对哪个状态的增量、预紧如何保留、执行多久、最大跟踪误差多少。将必要的限制放进规划或记录后处理残差，避免只报告未经执行的预测动作。

这些入口虽然读取指腹力，但主要将其用于初始化接触集合、动作屏蔽、阶段切换或停止判断；这与按实时力误差调节法向预紧的闭环不同。保留三维力传感能力，需要在低层真正用它调节载荷。

当前 Isaac 每个 `env.step` 是 `12/240=0.05 s`，部分桥接根据动作幅度执行多个 step；FREE 模型步长是 0.1 s。需要比较相同物理时间上的响应，并记录仿真时间与真实计算延迟。阻塞式服务器可以作为原型接口，Docker 本身不是已证实的失败原因。

### 7. 换指的凸包判据存在确定错误

`rl_isaaclab/scripts/regrasp_step.py:251` 的线性规划构造了两行位置平衡、一行权重和，但 `b_eq=np.zeros(3)` 令权重和为 0。全零权重总是可行，正常有限输入下三点及以上的这道可行性判断无法排除错误几何。

离线反例：三个点 `(0.03,0,0)`、`(0.04,0.01,0)`、`(0.04,-0.01,0)` 都在原点同一侧，当前函数返回 True；正确凸组合约束 `b_eq=[0,0,1]` 返回不可行。两点分支的“线段距中心小于物体半径”也不等同于中心位于凸包内。

修正几何判据后，它仍不是重力和摩擦下的支撑证明。是否释放一指还应依据剩余接触的载荷、滑移、物体运动及驱动余量。

### 8. 部分日志记录的是规划量，不能当成实测旋转

`regrasp_turn.py` 的 `yaw` 来自 `planned["yaw"]`，是模型预测的局部旋转，并非相机/仿真测得的物体净旋转。FREE/DROP/Jiang 的 `yaw_about_z` 则是有 ±π 分支的世界 Z 欧拉 yaw；圆柱倾斜后不等同于绕自身轴旋转，多圈还需要连续展开。

统一保存完整物体姿态、时间戳和任务轴，用相邻旋转增量在任务轴上的分量累计净转角，同时报告倾斜、漂移、掉落和回退。大步长下应使用一致的旋转分解，而非只减两次欧拉角。

## 面向五指绳驱动手的建议

### 观测与驱动

第一阶段采用已知圆柱尺寸和相机位姿。给圆柱加可追踪的纹理/标记；轴对称圆柱的轮廓不提供绕自身轴的角度，接触合力通常也不能唯一恢复这个角度。相机可先承担位姿和成功评估，再测降低视觉频率或移除视觉后性能如何变化。

三维力必须先变换到统一坐标，再按局部表面/指腹接触法向分解法向与切向。真实三维合力包含摩擦分量，不能直接归一化当作表面法向；当前仿真的 `normal_force_matrix_w` 已经把法向分量分离出来，属于不同观测。阵列在完成传感器标定后可提供接触区域、压力中心及滑移线索，不预设任意阵列图像都能直接量化滑移。

动作定义在独立电机位置、绳长或设备实际支持的控制变量 s 上。若有实际关节角，可用机构模型和实测 q 建立指尖雅可比；若只有电机编码器，必须处理绳松弛、回差、弹性与载荷相关耦合，不能将电机角直接当成各关节角。

用小幅、限载荷的实测动作标定局部响应，例如 `Δ物体位姿 ≈ A Δs`、`Δ指腹力 ≈ B Δs`，在接触模式改变后重估。可以用运动学作先验、在线拟合残差，不要求训练一个 RL 策略。局部辨识依赖有效激励及可观测性，不能保证任意驱动结构都能完成轴向旋转。

### 控制循环

1. 保持：建立各指的载荷目标、允许变化和最大力，稳定物体中心及倾斜。
2. 转动：小角度跟踪，测实际转角、载荷和滑移；按预测误差调整步长。法向保载与切向推动联合分配到电机/绳长，不能只把每根手指沿切向移动当作物体一定转动。
3. 建立备用接触：在当前手指耗尽行程前，把可达的空闲指送到下一工作区，确认持续接触并开始分担载荷。
4. 交接与复位：逐渐卸载将到限位的手指；物体稳定、其余指承担载荷后再释放，移动至下一工作区并重新接触。
5. 回到转动：用新的接触集合和局部模型继续累计旋转。出现载荷不足、显著滑移或漂移则转入恢复。

对于当前两指承载的姿态，先验证第三指能否参与交接更有价值。双指不意味着绝对不能旋转，但持续旋转所需的滚动、滑动或重建接触必须有明确机制。固定接触、只增加关节角且禁止卸载，通常会耗尽行程。

低层可从有约束的小步优化/QP开始。使用限位、速度、碰撞、最大载荷和接触保持约束；有可靠法向和摩擦下界时才使用对应摩擦约束。只有经验载荷下界时，要把它称为保载启发式并通过实验评估，不能称为力闭合保证。

### 实施与验证顺序

| 阶段 | 工作 | 建议验收 |
|---|---|---|
| A | 对齐坐标与重力、命令基准、物理步长；修正凸包；拆开求解器与手写动作 | 零动作能维持握持，小动作预测与实际的方向/尺度可解释 |
| B | 使用当前初始化，加任务资格检查，打通触觉保载下的小角度旋转 | 多个有效握持上稳定转 10–20°，无显著载荷失控和漂移 |
| C | 建立备用接触并完成一次卸载、复位、重接触 | 一次交接后仍握住，实际净转角保留，驱动余量恢复 |
| D | 重复循环 | 先完成真实累计 360°，再检验多圈和长时间持续性 |
| E | 第二种手及真实绳驱动手 | 共用任务/接触调度，仅更换手模型、驱动适配及少量标定 |

先选一个已校验的模型控制基线作对照，不再同时追三份未校验移植。FREE 当前保留自由物体状态，可作为优先排查的候选；这只是工程工作量判断，不是效果排名。Jiang 单自由度模型可用于受约束转动子任务，若用于悬空操作则需补支撑处理。DROP 应先修重力并验证动作后处理的影响。

每次运行保存初始 q 与位置目标、驱动/物体速度、位姿、五指三维力、原始/过滤/执行动作、接触模式、代码版本及最终配置。仅恢复 q 和物体 pose 不能保证恢复接触求解器状态；重复筛选或状态恢复后都需要重新稳定并验证初始接触。

跨手比较用相同的物理任务与反馈接口，允许每只手有不同初始握持。报告成功率、净转角/秒、维持时间、换指成功率、掉落率、峰值力、漂移和真实计算延迟。先用一小组不同有效握持调试，再在预先固定的一批握持、物体和驱动扰动上比较。

暂缓 GPIS/未知形状闭环作为主线。当前阻塞首先是模型与执行不一致、支撑和接触交接。未知物体探索可以在这个循环可靠之后加入。现有信念代码还把径向距离残差送给姿态方向的标量观测更新，需要先建立量纲和可观测性一致的观测模型，不能仅凭协方差随更新变小就声称姿态估计更准确。

可研究的问题是：只需每只手少量标定，接触级任务控制能否借助三维力反馈与局部在线辨识，在驱动耦合和接触变化下维持载荷并完成反复换指旋转。这是待实验验证的方向，不是本次代码审查已经证明的能力。
